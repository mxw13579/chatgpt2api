# R2 图片存储、免费额度与域名切换设计稿

状态：已按本稿实施代码与离线验证；真实 Cloudflare 资源尚未配置或验收，未部署。接入步骤及当前行为见 [使用说明](r2-image-storage.md)。

基线：`3bda523`。遵循 `AGENTS.md`：优先现有组件与小范围修改，每项新增状态只服务本稿中的具体需求。

## 1. 目标与决定

采用 **多账号 R2 Standard + 自定义域名直连 + Cloudflare 免费防护与缓存**。

- 每个 CF 账号配置一个专用图片桶，可绑定多个域名，指定当前返回域名和备用顺序。
- URL 图片在满足预算的账号中随机存放，返回该账号当前域名的图片链接。
- 默认及 `response_format=b64_json` 直接返回图片内容，不上传 R2，不保存图片或 Base64。
- R2 模式下，本地仅保存账号配置、额度状态和图片元数据；不新增原图、缩略图或图片缓存文件。
- 域名绑定、检查、切换、防护配置、额度与过期管理均可在前端操作。
- 不使用 Worker、Durable Objects、Redis、消息队列或新的数据库。
- 不做精确的“每张图片累计只能访问 N 次”；防刷采用按 IP 限速和 WAF，额度采用监测与停用。

图片访问路径：

```text
生成请求 → 应用获得图片 bytes
             ├─ Base64 → 直接返回客户端
             └─ URL → 预算筛选 → 随机账号 → R2 PUT → 返回当前域名 URL

图片浏览：客户端 → 自定义域名 → CF WAF/限速/缓存 → 对应 R2 桶
图片管理：前端 → 应用元数据接口；图片内容仍直接从 CF 获取
```

## 2. 实施前必须明确的边界

### 2.1 域名与账号

R2 直接绑定的自定义域名必须属于桶所在 CF 账号的 Zone。账号 A、B 使用各自托管的主域名；不能把账号 A 的一个主域名任意拆成子域名后直接绑定账号 B 的桶。

单桶当前最多可绑定 100 个自定义域名。首版不需要用满，每账号 2～3 个已激活域名即可。防止主域名过期时，备用域名应来自另一个已注册主域名，仅换同一主域名下的子域名不够。

域名注册、续费和外部注册商 NS 修改不在本项目内实现。页面负责已经接入 CF 的 Zone 的域名绑定和使用。

### 2.2 免费与计数

当前 Standard 免费额度：10 GB-month、每月 100 万 A 类、1000 万 B 类操作，R2 出站流量免费。以账号总用量考虑其他桶及备份，不能把每个桶当成独立免费额度。

存储计费参考每日峰值的计费期平均值。分钟级删除不能撤销当天已有峰值。用量统计不是实时计费闸门；本方案降低超额可能性，不承诺绝对零账单。多账号免费额度的适用以平台条款和实际账户计费为准。

### 2.3 域名检查

“服务器可达”“当前浏览器可达”“CF 已激活”是不同状态。国外服务器访问成功，不代表国内用户可达；失败也不能直接诊断为被墙。界面显示检查来源、时间和具体失败阶段，不显示未经证明的“已被墙”。

### 2.4 旧链接

切换域名只改变后续生成的 URL，以及应用重新解析出的历史图片 URL。已经复制到外部的旧 URL 无法自动改写。旧域名未失效时可继续服务；已过期或不可达时，用户需取得新链接。

## 4. 多账号与上传预算

### 4.1 账号配置

每条记录包括：内部稳定 ID、名称、CF Account ID、图片桶、S3 Access Key/Secret、CF 管理 API Token、启用状态、存储/A/B 预算、域名列表和当前域名。对象 key 固定在 `images/` 前缀下，首版不开放修改，确保和免费路径限速规则一致。

一个 Account ID 只登记一次，避免同一账号被误计成两份免费额度。图片桶不复用含配置、账号等敏感数据的备份桶。

凭据分工：S3 凭据负责对象读写；CF Token 负责 Analytics、域名管理、Zone 规则等。Token 仅授予对应账号/Zone 的必要权限。前端读取配置只得到 `has_secret` 类标记；未输入新值时保留旧值，永不把掩码字符串保存为密钥。

### 4.2 选择与预算

只有启用、配置完整、具有已激活的当前域名、全部公开入口已配置防护、用量数据未过期、预算足够的账号才参与随机选择。首次接入需成功刷新一次用量。是否纳入分配不依赖额外的后台域名探针。

上传前已有实际 bytes 长度，不用预估图片大小。锁内完成账号选择和容量预占；锁外发送网络请求，成功后锁内提交图片记录。

并发预占只使用当前单进程锁，不增加分布式机制。使用唯一对象 key，避免覆盖旧图而引入容量差额处理。A 类预算在请求发送前持久化增加，失败不能一概退回：部分错误和不确定结果仍可能消耗请求。

存储门槛采用已知图片容量及上传预占，并参考最近云端账号总容量。不要把账号总容量与已包含在其中的本地图片容量直接相加；最近快照后的新增量单独计入。尚未被云端快照反映的删除不提前从云端估算中扣减，宁可短暂少分配。专用账号外的其他写入只在下一次云端刷新后反映。

对象上传与 JSON 索引无法原子提交。最小处理是在 PUT 前保存待上传记录（key、账号、size、expires_at），成功后改为已上传；结果不确定的记录不公开展示、不立即释放预占，到期清理时按已知 key 删除。无需引入事务日志或独立恢复服务。

没有合格账号时，URL 请求明确返回容量/额度不可用错误，不自动切换 Base64 或本地落盘。可在调用上游生成前先检查是否有候选账号，但最终仍按真实大小判断。上传失败也不自动跨账号复制重试。

### 4.3 A 类操作最小化

- URL 每张图一次 PUT；不写图片时零 PUT。
- 列表读取本地元数据，不定时 LIST 全桶，也不逐张 HEAD 查存在。
- 普通图片不使用分片上传；删除用已知对象 key。
- 同步历史图片、连接测试等实际发生的对象操作也计入预算。
- 初始化 A 类预算计数参考云端本周期总量；此后本地发出操作即增加，云端刷新时取较高的累计值。这样不把完整云端值和完整本地值相加重复统计，但仍不是实时账单；外部操作及统计窗口的差异靠预留量和刷新控制。
- 计费周期边界与账户实际周期一致，用 UTC 表示；不能按进程启动时间或最近 30 天滑窗重置。无法确认周期时页面要求设置周期，不假定与用户当地自然月一致。

## 5. 用量监控与 B 类保护

通过 GraphQL 查询 `r2OperationsAdaptiveGroups`，按官方操作分类累计 A/B；显示统计区间和时间。不能将全部请求不分类型、状态直接当账单，部分失败请求也计费。查询账号总量用于预算，桶级量用于解释图片业务占用。

实现时先核对实际 API 的字段、action 值、查询跨度、保留期及采样口径，必要时按允许窗口分段汇总。缺失的时间段不能当作零；无法取得完整周期时显示统计不完整，不把部分数据标作完整免费余量。设计阶段尚未接入真实账号验证这些查询。

通过 `r2StorageAdaptiveGroups` 查询云端容量、对象数，分别展示当前容量、观察到的峰值和估计免费余量。10 GB-month 不是一个可与当前 bytes 简单相减的实时余额。

用量缺失或查询失败显示“未获取/未更新”，保留上次数据，不归零。定时刷新使用固定间隔，不增加失败后多层快速重试。超过数据有效期仅暂停新分配，Base64 请求和已知对象清理继续。

达到 B 类保护阈值：

1. 标记该账号因额度暂停，不再接收新图片。
2. 读取 CF 实际域名绑定列表，禁用该桶所有已启用的 R2 自定义域名（包括未在本地登记的绑定），并确保 `r2.dev` 关闭。
3. 页面显示每个域名是否确实关闭；CF 操作失败不能标成保护成功，下次正常维护周期再处理。
4. 其他账号继续服务；不迁移已存图片、不删除未到期内容。

保护是桶级停读，旧链接也会受影响；应用同时拒绝该账号的图片下载、ZIP 取图等主动 GET，保留元数据查询和删除。切换备用域名不能绕过额度暂停。恢复由管理员在页面明确执行并重新检查预算，不因统计波动自动打开。外部 S3 客户端仍可读取，故权限和额外使用方必须纳入账号预算。

公开访问和云端统计存在时间差，所以 B 类保护是止损措施，不是严格免费封顶。

## 6. 域名绑定、检查和切换

### 6.1 页面操作

每账号提供：读取可用 Zone、添加域名、查询绑定/证书状态、设置当前域名、调整备用顺序、启用/停用、解绑、立即探测。先添加并确认新域名激活、防护配置完成，再允许设为当前域名。

通过 CF API 操作桶的 `/domains/custom`；当前域名是本项目的选择，不需要搬移对象或改 key。解绑当前域名前需先选择替代域名，或者明确停用该账号的新上传。

新增公开域名会让整个图片桶可通过该地址访问。页面绑定时先保持停用，应用该 Zone 的防护配置后再启用。接入账号及变更域名时读取 CF 实际绑定列表；全部已启用域名都必须纳管并配置防护，或明确停用，不能只给当前域名加规则。未处理完的账号不参与新图片分配。

### 6.2 切换与检查的最小实现

首版采用页面手动切换，配合“立即检查”，不做定时探测、自动切回或多地区监控。用户可根据域名到期、访问反馈或检查结果自行选择备用域名。

- 从索引选一张仍在有效期内的图片，检查所选域名 DNS/TLS/HTTP；没有有效样本时显示“无图片探测样本”，仍可展示 CF 绑定状态，不专门上传探针图片。
- 前端另提供“从当前浏览器检查”，通过 CORS 实际读取一张有效图片；结果帮助当前用户判断，不能代表其他地区。
- 设为当前前确认域名已激活且防护已配置；即时读取失败时显示具体原因。管理员仍可基于本地网络情况明确选择该域名，不把服务器单点探测当成绝对事实。
- 切换只改变 `active_domain_id`；不更换存储账号，不重新上传，不自动解绑旧域名。
- 使用现有日志记录“旧域名、新域名、操作者、时间”，不保存凭据。

检查也可能消耗 B 类请求，应按需执行。错误信息区分超时、DNS、证书、HTTP 拒绝、无样本，不能一律解释成域名被封。后续确有自动切换需求，再明确探测位置和触发标准。

### 6.3 历史图片地址

持久化 `account_id + object_key + image_id`，不以旧完整 URL 作为唯一标识。管理页、任务查询和应用内历史对话显示时，根据账号当前域名重新解析；前端以 image_id 标识缓存，展示前检查 expires_at。

域名切换后，应用内旧图片无需复制即可用新地址访问。外部已经收到的旧 URL 不变，无法在旧域名完全失效后替用户重写。

## 7. 免费防护与缓存

### 7.1 防护模板

页面提供有限模板，不实现通用 WAF 编辑器：

- 图片路径前缀统一为 `/images/`，方便 Free 速率规则只按 Path 匹配。
- 每 IP/10 秒请求数可设，初始 120；超限 Block 10 秒。不对图片请求默认使用人机挑战，避免破坏 `<img>`、下载和 API 客户端。
- 一个可选自定义 WAF 规则限制图片域名只接收 GET/HEAD/OPTIONS；管理操作走私有 S3 API，不需要开放公开写方法。
- 不强制 Referer：第三方 API 客户端可能不发送它，且 Referer 本身不是可靠认证。

当前 Free 每 Zone 5 条自定义规则、1 条速率规则，速率规则字段/窗口受限。首版不允许在免费配置里填不支持的 Host 计数维度或任意时间窗口。同 Zone 多图片域名共用该限速规则；因此建议图片专用 Zone，避免同路径误影响其他业务。

规则按 Zone 管理，不按 CF 账号免费份额管理。多个备用域名位于不同 Zone 时，每个 Zone 都必须配置。记录本项目创建的规则 ID，只更新这些规则，不覆盖用户已有规则集。如果免费规则名额已用完，页面显示冲突并由用户选择处理，不能悄悄升级付费或删除已有规则。

R2 CORS 在页面配置允许的应用 Origin，允许 GET/HEAD，支持管理页下载、画布编辑及浏览器检查；可按公开图片 API 的使用方式选择 `*`。CORS 只控制浏览器读响应的权限，不承担防刷职责。

额度停读时禁用所有桶域名，不能仅封当前域名。平时也保持 `r2.dev` 关闭，防止绕过域名防护。现有匿名 `/images/...` 接口对 R2 图片只跳转至当前公开域名，不再由应用读取 R2 并代理内容；否则会绕过 WAF 和额度停读。管理员鉴权后的批量下载平时可单独读取，但同样计入用量，额度停读时也拒绝取图。

### 7.2 缓存与分钟级过期

第一版采用对象响应头：

```http
Cache-Control: public, max-age=0, s-maxage=60, must-revalidate
```

CF 使用源站缓存指令，Browser Cache TTL 选择 Respect Existing Headers；不配置长时间 Edge TTL 覆盖、不提供过期副本策略。Free 的规则强制 Edge TTL 最小值与源站响应头是不同机制，不能直接在面板强制填写 60 秒 Edge TTL。

清理任务正常情况下在到期后约 60 秒内发出删除；此前已缓存的边缘副本最多再保留其短 TTL。因此目标是无积压、网络正常时到期后约 1～2 分钟停止新的公网读取，不是精确到秒。实现验收要实际检查 Cache-Control、Age 和缓存状态，而不能只看配置已保存。

图片是静态对象，第一次被读取的时间可以晚于创建时间；缓存 TTL 不是图片业务 expires_at。严格的到秒拒绝不在本方案承诺内。

首版不做每图跨全部备用域名的自动缓存清除，避免为了极短收敛时间增加大量控制 API 调用。已缓存/已下载到用户设备的副本不可撤回。项目自身 IndexedDB 图片缓存应在展示时尊重元数据期限，不宣称能清除其他客户端的离线副本。

## 8. 过期清理与本地零新增图片

图片元数据至少保存：`id`、`account_id`、`object_key`、`size_bytes`、`created_at`、`expires_at`、MIME、宽高、上传完成状态。不保存 Base64 或临时图片文件。

扩展现有 `image_index.json`，在同一元数据文件中记录图片及 `r2_usage` 状态，用现有锁和临时文件原子替换。凭据继续放配置，不进入索引。当前规模不引入图片数据库或逐请求明细日志。

使用一个维护循环承接过期删除和到点用量刷新，复用 `api/app.py` 的启动/停止信号。每轮取到期记录，按账号复用客户端，网络 I/O 不持有索引锁；分小批处理，避免大批删除完全饿死用量更新。若有积压，页面明确显示，不继续声称达到一分钟目标。

删除成功或确认对象不存在后才清除索引、释放容量；失败保留到下个正常周期，显示最后错误。不为每个对象创建线程、定时器或重试队列。

原图展示直接从 CF 读取。关闭 R2 模式下的本地缩略图生成；图片管理使用原图懒加载和分页。单张下载可由浏览器直接读取，批量 ZIP 沿用应用内存打包并通过存储服务读取，不落盘。该操作会消耗相应 GET，应计入 B 类用量。

任务成功结果只保存 image_id/归属/期限及必要元数据，查询时补 URL。检查续轮询等分支，不能再次把 Base64 写进任务 JSON。输入参考图继续在内存处理，不复制到本地历史目录。

## 9. 前端设计

在现有设置页新增“图片存储”页签，把现有 WebDAV 大表单从基础设置中移到这里，不重做整个设置系统。

### 9.1 全局设置

显示当前模式、图片保留分钟数、清理/用量刷新时间、账号总数、可分配账号数。提供立即刷新用量、立即清理到期记录。默认值可编辑但不暴露无必要的内部状态参数。

### 9.2 账号列表

| 展示列 | 内容 |
|---|---|
| 账号 | 名称、桶、启用状态 |
| 当前域名 | 当前返回地址、已激活备用数 |
| 容量 | 项目容量/预占、云端账号容量、预算 |
| A/B 操作 | 云端统计、本地 A 类预算计数、预算及数据时间 |
| 状态 | 可分配、配置不全、无可用域名、用量过期、额度暂停 |
| 操作 | 编辑、连接测试、刷新用量、域名管理、防护配置、启停 |

用量页展示“估算免费余量”，不能标成“保证免费剩余”。停用账号只停止新上传；清理旧对象继续。存在待上传或未删除对象时，不允许删除账号凭据或修改其 CF Account ID、图片桶；否则旧对象会丢失定位。此时仍允许同一存储位置的凭据轮换、域名切换和停止新分配。

### 9.3 账号详情：域名与防护

- 域名列表：域名、Zone、CF 激活状态、规则配置结果、服务端探测、当前浏览器探测、最后检查时间。
- 操作：添加、启用/停用、解绑、设为当前、调整备用显示顺序、立即检查。
- 防护表单：IP 请求阈值、只读方法规则、源站缓存配置、CORS 允许来源、r2.dev 关闭状态。
- 应用规则显示实际 CF 执行结果；权限不足、规则槽占用或证书未激活时保留明确错误。
- 额度保护恢复使用明确的“恢复公开访问”操作，展示将重新启用的域名，不与普通账号启用开关混为一谈。

### 9.4 图片管理

列表显示账号、大小、创建/到期时间、当前 URL、存储状态；提供复制最新链接、浏览器下载、删除。按账号和到期状态筛选。

Base64 请求不进入持久图片列表，并在设置说明中写清。过期图片不继续自动加载远程原图。刷新列表即可得到域名切换后的地址；应用内对话读取的历史图片也按 ID 解析，不能只修管理页面。

## 10. 后端改动边界

| 文件/模块 | 主要改动 |
|---|---|
| `services/r2_client.py`（新增） | 提取现有备份 R2 对象客户端；保留 PUT/GET/DELETE，不复制签名实现 |
| `services/cloudflare_api.py`（新增） | 用一个简单客户端封装 Analytics、域名及 Zone 规则 HTTP 调用 |
| `services/backup_service.py` | 导入提取后的客户端，备份内容、桶和调度保持原语义 |
| `services/image_storage_service.py` | 多账号选择、预算、元数据、URL 解析、过期删除及域名选择 |
| `services/config.py` | 图片 R2 配置、默认值、边界校验及秘密字段更新约定 |
| `services/protocol/conversation.py` | Base64 分支不保存；URL 分支上传并传递图片归属元数据 |
| `services/image_task_service.py` | URL 结果只保存元数据，历史查询动态解析域名，覆盖续轮询结果 |
| `services/image_service.py` | 远程图片管理/下载，R2 模式不写缩略图或扫描本地图片目录 |
| `api/image_storage.py`（新增） | 管理路由；不要继续扩大 `api/system.py` 的配置职责 |
| `api/app.py` | 注册管理路由与一个维护循环，R2 模式停用旧本地图片清理任务 |
| 前端设置、图片管理、历史图片缓存 | 按第 9 节调整，沿用现有请求和状态管理方式 |

主要管理接口建议复用 `/api/image-storage` 前缀：

- `GET /api/image-storage`：配置公开投影、账号状态、用量。
- `PUT /api/image-storage`：保存全局设置与账号配置。
- `POST /api/image-storage/accounts/{id}/test`：连接和权限测试。
- `POST /api/image-storage/accounts/{id}/usage/refresh`：刷新用量。
- `GET/POST /api/image-storage/accounts/{id}/domains`：查询/绑定域名。
- `PATCH/DELETE /api/image-storage/accounts/{id}/domains/{domain_id}`：状态、优先级、当前选择/解绑。
- `POST /api/image-storage/accounts/{id}/domains/check`：服务端域名检查。
- `PUT /api/image-storage/accounts/{id}/protection`：应用有限防护模板。
- `POST /api/image-storage/accounts/{id}/access/restore`：预算检查后恢复公开访问。
- `POST /api/image-storage/cleanup`：立即清理到期元数据及对象。

管理操作沿用管理员鉴权、线程池和脱敏错误。新增图片归属字段优先用于内部任务/管理响应，公共 OpenAI Images 接口仍保持默认/Base64 只返回 b64_json、URL 只返回 url 的约定。

## 11. 旧数据与实施批次

首版新增明确的 R2 模式，不在配置缺失或上传失败时回退本地/WebDAV。旧模式保留现有入口，选择 R2 后所有新图片遵守本稿规则；不同时双写。

现有本地/WebDAV 历史数据不因切换自动删除。首版保留旧记录的只读访问和显式删除能力，R2 模式下不为它们生成新的本地缩略图。达到本地完全无图，需要用户明确清除原有原图、缩略图和旧任务里的图片内容；页面展示这些待清理项，不能把“以后不写图”宣称为“旧图已清空”。

历史图片批量迁移 R2 不作为首版必做项。如需保留旧图再清空服务器，另行实现一次性迁移：上传并验证成功后再单独清除源数据，遵守相同预算和 `images/` 前缀；不在本次设计中扩展通用迁移系统。

原定按可验证的五批实现并分别中文提交（实际按共享客户端、存储、链路、管理及前端分组）：

1. 提取 R2 客户端、配置多账号、Base64 不保存/URL 上传、最小元数据；加入对应前端配置。
2. 存储预占、A 类预算、云端用量、分钟级清理和账号状态展示。
3. 域名绑定、当前/备用选择、历史 URL 动态解析及页面管理。
4. 免费防护/缓存模板、CORS、B 类保护停读和按需域名检查。
5. 图片管理/任务/浏览器缓存收尾、旧数据显式清理入口，部署文档与整体相关回归。

每批不自动发版；整体完成后再进行一次发布验收。

## 12. 验收重点

- Base64 生成/编辑/Chat/Responses 均不上传、不写图片；URL 只返回 URL，保存到一个账号。
- 并发请求不重复使用同一份剩余容量；本地 A 类预算重启不清零，不错误相加云端总量。
- 用量查询按账号聚合，过期数据不归零；额度暂停不能被域名切换绕过。
- 待上传/已上传对象都能按 key 到期清理；删除失败不提前释放容量。
- 自定义域名绑定到同账号 Zone；当前/备用域名均有防护，r2.dev 关闭。
- 页面切换不复制图片；管理页和应用内历史解析出新 URL，外部旧 URL 的限制有明确说明。
- WAF 规则不覆盖用户已有规则；Free 不支持的字段/名额不能伪装成功。
- 验证实际 CDN/浏览器缓存头和正常情况下约 1～2 分钟过期收敛。
- R2 模式不新增本地原图/缩略图/Base64 任务文件；批量下载不落盘。

自动测试继续使用 `test/run_isolated.py` 的合成配置与网络 mock，针对变更分支验证；前端做类型/构建及相关交互检查。上线前另用一个测试桶验收真实 CF 域名、规则、缓存及用量查询；合成测试不能替代这一步。测试桶操作和部署不属于本设计稿交付动作。
